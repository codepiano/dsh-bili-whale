# 概念维护与宿主观察

2026-11-01 起，后台自动概念提炼已停用。概念由鱼在主会话中结合实际阅读、理解和反思，通过现有 MCP 工具直接维护；不再由另一次模型调用从主人消息、鱼的回复或视频正文生成候选。

## 当前行为

- `session/event` 继续保存原始观察事件；主人私信、评论投递不再创建学习任务。鱼的操作汇报也不会再被后台当成概念。
- 材料取得、工具回执、正文分页和模型送达确认继续记录；阅读完成不等于概念已写入。
- `turn/end` 不入队、不把旧任务置为 ready、不补入漏掉的来源、不唤醒后台模型。宿主启动不恢复历史学习任务或启动自动人格反思；历史队列、候选、概念群和版本保留原样。
- 主会话用 `concept_catalog`、`concept_query` 查群及成员，比较同义表达。相同概念复用原 ID；确有新增才用 `concept_propose` / `concept_review`，群定义用 `concept_catalog_update`。写后查询核验。
- 不收操作流水账、保存成功、任务进度、后续计划和元数据维护说明；不因换来源、换群、换说法而重复新增。详细规则见 [鱼的维护 skill](../skills/fish-concept-maintenance/SKILL.md)。语义查重由鱼根据实际查询结果判断，不宣称工具自动识别所有同义概念。

## 配置与已有能力

`observe=true` 继续启用宿主观察。`learning` 保留兼容：false 时暂停动态概念上下文准备；true 允许准备已有概念上下文，**不会启动后台提炼**。`mode=shadow` 只记录上下文预览，`active` 才把已有概念与阅读指引交给鱼。已有 feed 兴趣竞争、疲劳记录及显式 MCP 写入不因本次修改而关闭。

不修改历史数据库，不清理已存在的操作汇报或重复成员；观察页仍可只读检查。历史提炼器的实现和单元测试保留作兼容与审计用途，宿主不再调度它。

## 验证边界

隔离临时数据库验证主人消息、鱼回复、外部投递、视频回执和回合结束不再创建/执行学习任务，历史 pending/validated 任务与概念状态保持不变；同时检查动态上下文、阅读完成和送达记录继续有效。测试不调用真实模型，也不写在线概念数据。
