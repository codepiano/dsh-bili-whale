# 决策观察与关键文件版本设计草案

日期：2026-10-27。状态：设计基线。首版已在开发分支实现，当前能力与限制见[第一版使用与验证](CONCEPT-SYSTEM-V1.md)，尚未合并或发布。配合[概念集合与偏好系统设计](CONCEPT-SYSTEM-DESIGN.md)，让每一次选择能追溯到当时的来源、集合状态、实际输入和模型输出，并观察人设及学习倾向的演变。

观察的核心单位是一次运行 trace，而不是单独一条 MCP 调用。一次回复可能同时受人设、既有会话上下文、学习状态和本轮素材影响；仅保存决策胜负不足以解释行为。

## 每一次运行的证据

| 层次 | 保存内容 | 可以回答的问题 |
| --- | --- | --- |
| 运行环境 | 插件 Git 提交、算法与配置版本、宿主版本、可获得的模型标识与生成参数 | 当时运行的是什么版本 |
| 输入来源 | 用户原话或视频引用、采集范围、候选提取结果、上下文引用 | 候选从哪里来，有没有误读 |
| 决策输入 | 问题、分层候选、集合与成员版本、强度、相关度、论据、疲劳 | 哪些因素参与了竞争 |
| 计算过程 | 各项贡献、归一化结果、扰动种子与值、淘汰与平手处理 | 为什么程序给出这个建议 |
| 模型输入 | 当次实际组装的提示、人设与 personal 渲染段、文件版本、截断情况 | 系统实际向 DS 提供了什么 |
| 模型响应 | 正文、工具调用与结果引用、可获得的推理内容、解释摘要 | DS 实际返回和执行了什么 |
| 后续结果 | 实际选择、建议覆盖、动作成功与否、反馈、状态更新 | 建议是否被采用，后来发生什么 |

候选原文、推理和完整提示放在本地证据对象中，时间线默认显示摘要与引用，避免一次查看输出大量私人内容。模型参数未知时标记未知，不从应用默认值猜测实际调用值。

## DS 的思考内容

采集 DS 经接口返回、且宿主实际保存或能够合法读取的推理内容。如果宿主只保存摘要，就标记为摘要；没有返回或无法采集时，标记不可用及原因，不补写或伪造“完整思维链”。首先检查 DSH 保存格式和可用事件接口，再决定采集适配器。

决策工具另外要求一段简短的可审计理由：关键依据、备选项、主要不确定性和覆盖原因。这是对外解释，不标成模型内部过程。记录至少区分 `provider_reasoning`、`host_summary` 和 `decision_rationale`，并保留采集位置和时间。

推理流在响应完成后归档；中断的响应保留 `partial` 标志。没有稳定的响应 ID 时，最多关联到会话轮次并标记不确定，不靠“时间接近”把所有调用算作同一决策。采集已返回的内容不要求 DS 额外生成隐藏的思考过程。

## 关联与时间顺序

使用 `trace_id` 关联一次任务，`decision_id` 关联一次竞争，`parent_decision_id` 表示分层选择，`session_id`、`turn_id`、`response_id`、`tool_call_id` 关联宿主事件。拿不到的标识显式留空。

所有事件带稳定事件 ID、事件类型、UTC 时间、时区、单调递增序号、来源和前后状态版本。界面按 Asia/Shanghai 展示。重试与原调用通过幂等键关联；同一调用的开始、成功、失败和结果未知必须区分。

建议事件序列：

```text
source.observed
candidate.proposed → candidate.reviewed
snapshot.captured → decision.previewed → decision.committed
personal.rendered → prompt.prepared → prompt.accepted
response.completed → action.observed
feedback.recorded → state.updated
```

这不是强制直线流程。一次任务可以包含多次提取、决策和响应，每个事件都有独立状态；网络中断后记录缺口。`prompt.accepted` 只证明宿主接收请求，不能证明模型接受了观点。

## 关键文件的版本化

### 记录范围

| 文件或状态 | 记录方式 |
| --- | --- |
| `~/.bili-ai/persona.md` | 内容快照、内容哈希、差异、修改来源与说明 |
| personal 状态及渲染结果 | 结构化版本及实际注入文本分别保存 |
| 概念成员、集合和关联 | 修改事件及可读取的状态快照 |
| 相关配置 | 决策和注入所需字段的版本；排除凭据和其他无关秘密 |
| 日记与记忆来源 | 保存当次实际读取的内容或片段、版本和范围，不只存路径 |
| 实际提示 | 保存字节一致的组装结果、所用输入版本与段落边界 |
| 代码与模板 | Git 提交 ID，加运行时模板哈希；有未提交改动时额外记录差异哈希 |

不得把凭据文件、Cookie、会话令牌或带鉴权的媒体 URL 放进观察记录。归档模板和配置使用字段白名单；日志入口处理凭据泄漏，原始推理和正文也按同样规则检查。需要脱敏时，明确保存的是脱敏视图，不能声称与原始字节完全一致。

### 快照和修改

版本使用内容哈希识别实际内容，不以修改时间代替版本。每次决策和注入前读取一份确定的内容快照，从该快照组装输入，并记录最终送往宿主的内容；文件在此后发生变化也不影响本轮使用的版本。

关键文件变化由 watcher 提醒，在关键使用点再次读取并比较哈希。外部编辑者无法识别时记为 `external_unknown`，不猜测是用户还是 DS。文件被删除、无法读取、恢复备份也是事件；中间修改未被观察到时，承认采集缺口，不伪造完整编辑历史。

系统自己的更新要先记旧版，再原子写新版本，并带预期旧版哈希。若用户已修改，更新冲突并保留双方版本，不覆盖。首版关键状态使用同一写入队列或事务边界；提交事件与状态版本一致，崩溃恢复不能出现已更新状态但找不到对应决策的静默情况。

恢复旧版时追加一个恢复事件和新版本，记录来源版本与原因。恢复不能重发评论、私信或其他外部动作，也不能擦掉后来发生的历史。

### 人设注入去重

插件已有“每会话减少重复人设”选项。开工时应将 personal 渲染段纳入有效注入内容的哈希，而不只比较 `persona.md`。学习状态变化后，即使人设文件没改，也需要按明确策略提供新的附加段落。

当前宿主接入实现改为独立的动态 context：每次 assembly 重新渲染，由 DSH 原生上下文投影按文本去重，不再依赖调度器人设哈希。分别记录 context_prepared、context_step 和实际观察到的 context_admitted，避免把准备成功当成模型已收到。细节见 [宿主自动学习](AUTOMATIC-LEARNING.md)。

日志要区分“文件发生变化”“渲染结果变化”“提示已组装”“宿主已接收”“DS 返回回复”。若本轮因为去重没有重新注入，关联上次已确认注入版本，并记录本轮只有提醒语。不能看到磁盘上的新文件，就宣称该版本已经影响 DS。

## 本地存储边界

建议在用户数据目录中使用插件拥有的观察存储，例如：

```text
~/.bili-ai/concept-system/
  observations.sqlite3 SQLite 事件 状态 版本 预演与回执
  objects/             按内容哈希保存的快照与响应证据
  journal.json         升级前的原始日志 如存在则迁移后保留
```

上述路径是待实施设计，不在生成文档时创建或迁移。首版采用 SQLite 事务记录与内容寻址快照；迁移规则见[第一版使用与验证](CONCEPT-SYSTEM-V1.md)。不为私人文件建立 Git 仓库。项目 Git 保存代码、模板和设计；真实人设、聊天、日记、推理与学习记录留在仓库外，不推送公共 fork。

为归档设置本机访问权限及保留策略。首版默认不自动清除审计证据，展示体积，由用户明确触发清理或导出；若移除内容，保留“证据已清理”的标记，不能仍显示可完整重放。导出前可预览字段并脱敏，不默认上传任何观察数据。

## 怎样观察系统

首版提供 MCP、CLI 查询及 Mantine 本地只读页面。页面支持集合、决策与关键文件版本查看；MCP 与 CLI 保留更细的事件筛选和证据读取。启动及权限边界见[第一版使用与验证](CONCEPT-SYSTEM-V1.md#mantine-本地观察页面)。

一次决策详情应并排展示：

1. 当时有哪些候选，各集合支持或反对什么。
2. 基础权重、当前疲劳、扰动分别贡献多少。
3. 程序建议、DS 实际选择及覆盖理由。
4. 实际注入的 persona 与 personal 版本，以及相对上次的变化。
5. DS 响应、可采集推理内容和简短决策理由的独立入口。
6. 后续反馈、哪些状态因此更新，以及没有证据的部分。

长期视图关注：哪些集合在增长，增长来自多少不同来源；哪些词句反复使用；疲劳是否让其他选项得到机会；DS 多常覆盖程序建议；候选评估是否把用户否定或引用误判为喜欢。

“词句被提供给模型”与“词句实际出现在回复中”分别统计。相同词句自然出现也可能与注入无关，不能把匹配次数直接算作因果效果。

## 重放与影响评估

计算重放使用保存的输入、状态快照、当时时间、算法版本和随机种子，在隔离目录重算得分；不更新真实学习状态，不发出任何平台动作。使用新算法重算时记录为对照运行，关联原决策，不覆盖原结果。

模型响应不承诺逐字可复现。可以在独立会话中对照注入前后的版本，固定其他可控输入，分别记录模型配置与结果。第一版先观察关联与建议采纳，后续由用户决定是否开展模型对照实验及其调用成本。

原会话中的历史上下文可能继续影响行为；版本回退也不能删除模型已经看过的内容。因此“切换回旧 persona 后回复仍变化”不自动证明版本系统失效。若无法保存或枚举宿主实际使用的完整上下文，清单标记覆盖范围，不能声称已重建全部模型输入。

## 首版验收

- 从一条决策能找到当时的集合状态、计算细项、输入快照和实际选择。
- 外部编辑人设可被观察；决策和注入使用确定版本，后续文件变化不会改写历史证据。
- 能区分推理原文、宿主摘要、决策理由和不可采集状态。
- 相同幂等键重试不会重复学习；中断和采集失败显式可见。
- personal 变化、去重跳过和实际注入回执均有记录。
- 能比较两个关键文件版本并在隔离环境重放计算，不触发外部动作。
- 观察存储和公开代码仓库分离，导出不会默认携带凭据或私人原文。

## 实施前检查

确认 DSH 可获得的轮次与响应标识、推理保存格式、提示提交回执及 MCP 接入能力，再确定采集范围。无法取得的证据应降级为明确标记，不能通过猜测填齐。

首版必须先有观察记录再启用学习更新。模型或文件采集缺失时，至少保存结构化决策及缺失标记；无法持久化关键决策与更新事件时，本次学习提交失败并保留旧状态，不能继续做无法追溯的权重更新。
