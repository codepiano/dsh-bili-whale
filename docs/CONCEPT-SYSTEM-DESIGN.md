# 概念集合与偏好系统设计草案

日期：2026-10-27。状态：设计基线。首版已在开发分支实现，当前能力与限制见[第一版使用与验证](CONCEPT-SYSTEM-V1.md)，尚未合并或发布。开发完成后可以提交，合并、发布和服务重启等待用户明确要求。

第一版要让鱼从对话和观看经历中持续积累概念，通过集合之间的竞争形成内容选择与表达倾向，并留下可回看的证据。先实现一个粗糙但完整的学习循环，再根据实际效果调整机制。本文描述行为模拟，不将权重或语言表现当作主观意愿的证据。

## 已确定的方向

相近的东西组成集合，保留各成员的内容与来源，不因为相近就合并。集合随着历史不断丰富，积累越充分，参与竞争时越有分量；重复收录同一来源不能靠数量无限增加权重。

兴趣、观点、词汇、口癖、惯用句式、成语共用底层结构。它们通过用途、关系、触发场景和当前状态区分。同一个成员可以属于多个集合，一个集合也可以与其他集合建立联系。

系统引入疲劳、赏罚和小幅扰动。长期积累、当下疲劳与结果反馈分别保存，避免一次落败就丢掉历史，也避免赢家不断奖励自己。

用户的兴趣与鱼形成的兴趣分别记录。用户说过某个词，只能证明提及过；鱼自己反复选择某类内容，也不能反推用户喜欢它。

## 第一版数据模型

### 成员与集合

| 对象 | 最少记录的内容 |
| --- | --- |
| 来源 source | 来源类型、用户或鱼或第三方、会话与消息或视频引用、原文片段、发生时间、采集时间 |
| 成员 item | 稳定 ID、内容、用途标签、来源引用、适用场景、触发线索、反例或不适用场景、候选状态 |
| 集合 collection | 稳定 ID、名称、成员引用、相关集合、基础强度、证据计数与近期状态 |
| 关联 membership | 成员与集合的关系、适用情境、关联强度、建立原因与版本 |
| 决策 decision | 问题、候选、参与集合、评分依据、疲劳、扰动、选择、覆盖及实际结果 |
| 反馈 feedback | 对应决策、反馈者、反馈内容与类型、可信程度、影响范围、更新前后值 |

用途标签先允许 `topic`、`belief`、`motive`、`word`、`phrase`、`idiom`、`sentence_pattern`，不规定互斥类别。相近成员可以有相似关系；完全相同来源的重复采集应按来源 ID 去重，重复出现的表达另记出现次数。

词语的表面相同不代表含义相同。例如“克制”作为常用词和作为“不轻易打扰”的判断依据，可以保留不同成员，再建立联系。成语可以同时关联一个场景集合和一个表达模式集合。

### 兴趣与概念集合的关系

第一版把兴趣建模为概念集合对注意力的吸引状态，不单独建立一棵固定兴趣树。每个集合可分别记录：

| 状态 | 含义 |
| --- | --- |
| familiarity | 已经接触和理解的程度 |
| affinity | 喜欢或认同的程度，可为负 |
| curiosity | 尚未解决的问题及继续探索的倾向 |
| fatigue | 在某种场景下近期反复使用或接触后的疲劳 |
| confidence | 这些状态获得多少有效证据支持 |

熟悉、认同和兴趣不能共用一个数字。“很熟悉、不认同、仍想研究、今天看累了”是合法状态。底层结构统一，也不要求每个成员都填写全部状态。

## 从经历到候选

从用户对话、鱼的观看经历和后续反馈中提取候选。提取结果必须携带原句与上下文，并区分直接表达、引用、否定、玩笑和推测。候选先进入待评估，不直接改写人设或获得高权重。

例如“最近想了解康德”支持近期学习兴趣；“这个视频提到了佛教”只支持建立一个待评估的主题线索；“不想再看这种康德解读”可能针对表达形式，不能直接把整个康德集合判为负兴趣。

候选评估后可以加入一个或多个集合，也可以暂缓或拒绝。评估理由、使用的模型和来源版本进入记录。历史内容中出现的命令属于素材，不能据此提升权限或改变工具边界。

## 竞争与选择

### 内容选择

允许逐层竞争，但不把它固化成互斥目录：

1. 当前动机竞争，例如娱乐、学习、休息、探索陌生内容。
2. 主题与形式组合竞争，例如轻松纪录片、动漫、哲学讲解。
3. 在真实检索到的视频候选中选择，结合质量、适用场景和重复情况。

纪录片可以同时服务娱乐与学习，康德与动漫也可以通过自由意志等主题建立联系。每层候选、得分、淘汰原因和父决策 ID 都要保留，不能只记录最终视频。

### 表达选择与模仿

从用户话语中提取词汇、成语、句式和使用场景，经过候选评估后，形成可供使用的表达素材。鱼接触的其他内容也能提供素材，但来源须与用户用语区分。

表达集合参与“当前怎样说更合适”的竞争。第一版每次只选少量相关成员，形成简短的表达提示；允许不使用任何素材，不强制插入口癖或成语。实际回复是否使用、用在何处、是否被用户纠正，作为后续观察与反馈。

来源中的事实立场、表达习惯与用户当前请求分开处理。学会某种说法不等于认同其中观点，也不应覆盖用户本轮明确的语气要求。

### 评分与扰动

首版评分建议采用可拆解的结构，具体系数在实现前确定并版本化：

```text
基础贡献 = 集合强度 × 当前相关度 × 论据强度
候选得分 = 各集合的有符号贡献之和 − 当前场景疲劳惩罚 + 有界扰动
```

各项先归一化，避免靠成员数量或随意填写的强度碾压其他因素。第一版集合强度随有效证据及不同成员增加而有界增长，重复来源的增量递减；先不实现复杂的语义独立性估计。多集合共享同一成员时保留贡献出处，避免在一次决策中重复计入同一证据。

模型负责提出候选、关联、论据与简短理由；程序负责校验输入、计算、抽样、记录和状态更新。第一版不额外调用另一个模型制造“对抗人格”；可由当前 DS 会话通过 MCP 提交结构化评估。这仍是模型提供论据的机制，不能把程序算分称为完全客观判断。

扰动使用记录下来的种子与算法版本。首版只在得分接近的合规候选间产生小幅影响，差距阈值及幅度可配置；不得影响权限、账号边界、发送额度、凭据保护或平台暂停等硬约束。

### 疲劳与赏罚

疲劳按集合和场景记录，例如选片、表达、分享。连续使用后暂时降低影响，随时间恢复；“最近总看哲学”与“最近总用某个成语”可以分别疲劳。时间衰减的计算时刻及使用前后值必须保存，支持重放。

奖励或惩罚来自选择后的证据，例如用户明确反馈、预期是否实现、内容是否确有价值、鱼后来是否修正评价。单纯赢得竞争不奖励，输掉竞争也不自动惩罚；模型自评与用户反馈分别标注，可靠程度不相同。

无反馈保持未知，不把用户沉默当作负反馈。平台发送失败也不等于该主题不值得看。首版先使用有上下限的小幅更新，记录原因和范围；更新幅度、恢复速度与扰动系数属于待定参数。

## MCP 与宿主分工

MCP 提供模型可以调用的接口；持久化、算分与日志属于插件拥有的同一业务核心。CLI 与 MCP 复用核心，不再各自维护一份默认值或状态。具体传输方式和 DSH 注册方式在开工时检查宿主支持后确定，不在此承诺已接入。

| 拟定工具 | 行为 |
| --- | --- |
| `concept_propose` | 提交携带来源的候选，不直接激活 |
| `concept_review` | 记录评估，接受、暂缓或拒绝候选并建立集合关联 |
| `concept_query` | 按场景、主题、用途检索相关集合和成员 |
| `decision_preview` | 基于指定状态版本算分，只预演，不更新权重或疲劳 |
| `decision_commit` | 固化选择与理由，按幂等键记录使用和疲劳 |
| `decision_feedback` | 关联后续反馈，追加一次可审计的赏罚更新 |
| `personal_render` | 返回有长度预算的当前兴趣与表达提示，以及所用版本 |
| `trace_get` | 查看一次决策及关联证据，默认返回摘要 |
| `version_list` 与 `version_diff` | 查看关键文件和状态版本；恢复作为单独显式操作 |

预演与提交分开，MCP 重试不能重复学习或重复累积疲劳。状态冲突时重新读取并预演，不能悄悄用旧版本覆盖新状态。第一版决策只产生建议；DS 可以覆盖建议，但要记录实际选择与覆盖理由。已有评论、收藏和私信工具继续承担发送保护，决策工具不获得直接发送能力。

## 人设与运行状态

`persona.md` 保留用户和鱼维护的显式人设。`personal.json` 保存从历史形成的集合倾向与最近变化；渲染结果是附加段落，不自动覆写 `persona.md`。首版附加段落以 400 字为建议预算，最终值配置化，超出时记录被排除的条目与原因。

用户的当前指令与明确人设约束先于学习倾向；学习倾向与词句素材不能扩大权限。关键文件由观察机制版本化，外部手动编辑也要留痕。具体存储、注入确认和事件关联见[决策观察与关键文件版本设计](DECISION-OBSERVABILITY.md)。

## 第一版交付顺序与验收

先实现来源、候选、集合、决策与版本记录，再接入 MCP 预演和回看；之后接内容选择与表达素材的实际注入，最后打开疲劳和反馈更新。先以影子模式运行，只记录建议与 DS 的实际选择，不影响现有行为；用户决定何时启用实际影响。

验收至少包含：

- 相近成员组成集合且保留各自来源；同一个成员能关联多个集合。
- 用户提及“康德”进入候选，明确兴趣与单纯提及产生不同结果。
- 相同输入、状态、时间、算法版本和种子产生相同分数；预演与重试不污染状态。
- 连续使用产生场景内疲劳，时间恢复不抹去长期积累；内部胜负不自动赏罚。
- 能看清娱乐与学习到具体视频的选择路径，也能记录不看、暂缓或覆盖建议。
- 能从一次回复追到实际提供的表达素材、关键文件版本及可用的宿主回执。
- 所有验证在隔离目录、临时数据和独立服务中进行；不对真实账号测试发送。

## 开工时需要落实的选择

集合强度增长、疲劳恢复、赏罚幅度和扰动的具体参数尚未定稿。应选一组小而可解释的默认值，通过配置版本和影子记录迭代，避免先建复杂机制。

现有 `whale-work/pref/pref.mjs`、`concepts.json` 和 `choices.jsonl` 是原型输入。旧规则中“赢家加 0.15，输家减 0.05”不沿用为正式学习规则。迁移需保留原始事件和旧规则版本，不把事后补记解释为当时已经由程序计算。实际迁移与导入需要在实施阶段完成，不因生成文档而执行。
