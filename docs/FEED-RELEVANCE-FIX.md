# 选题清单偏题问题：真实记录分析与修复

2026-10-28 的两轮只读验收暴露了准入与评分语义叠加的问题。此处只保留可复核的公开视频 ID 和汇总；私人会话、完整概念状态、模型原始记录不入库。

## 原因

平台搜索按“迭代、维护、复盘、技术债”等词返回了手机传闻和游戏赛事内容。这些候选进入待评估池本身不等于入选；需要后续语义评估决定是否适合当前探索目标，不能只用主题词黑名单过滤。

模型在理由里明确说“与 three.js 或工程维护无关”，却给了 0.02、0.05 的非零相关度。旧准入条件只要求 `relevance > 0`，这些候选仍然进入竞争。与此同时，“克制，所以跳过”的立场被给了正强度；程序将其作为阅读加分，且立场分项的 relevance 固定为 1，足以掩盖很小的探索贡献。后续逐槽选片又持续填到 n，导致偏题候选进入清单。

因此主要问题在**竞争前的相关度准入与立场评分语义**，不是搜索接口返回噪声本身，也不是需要关闭疲劳或扰动。

## 变更

- 新准入策略 `feed-relevance-v1`：低于 0.5 不参与竞争，允许不足 n 条或空清单。0.5 是当前粗粒度策略阈值，尚未通过大样本校准。
- 准入后的立场贡献乘以实际探索相关度，不再固定为 1；通用决策算法与旧决策重放语义不变。
- MCP schema、工具说明、候选包和自动续步统一说明：strength 正值支持阅读，负值建议跳过，无关为 0；不是与立场一致的程度。
- 为每条候选记录是否准入及原始理由、引文。被过滤项不产生选题决策、疲劳或发现候选，不回填旧排序。
