# 鱼的阅读后技能与知识库

专属 skill 源文件在 `skills/fish-concept-maintenance/SKILL.md`。部署时仅复制到鱼的 cwd 下 `.agents/skills/fish-concept-maintenance/SKILL.md`，不安装到 Codex/DSH 全局目录。鱼插件同时注册按鱼 cwd 过滤的原生技能提供器，即使全局 filesystem/tool-skill 关闭仍可发现本技能，并通过阅读后的原生上下文提供正文；不改变其他会话的全局开关。后台学习直接加载同一版本，响应回执记录 skill 名称和内容 SHA256。

概念群服务决策、兴趣、探索目标与归属；Nowledge Mem 是知识库，保存具体读了什么、内容总结、鱼自己的理解/想法与待查问题。日记是生活/反思记录，既不替代知识库，也不把第三方观点直接变成主人偏好或 persona。

沿用现有流程：实际视频正文全部页交付 → 阅读完成 → 当前鱼会话装配专属 skill 和待保存 read_id → 鱼写总结 → video_knowledge_save → nmem 稳定 ID 写入并实际读回 → knowledge.saved 与 memory_id。不新增每日定时任务或自我唤醒消息。概念提取/归属仍在既有回合后学习队列处理，具有来源、理由与版本。

`video_knowledge_save` 接受 read_id、summary、thoughts、questions、quotes[{source_id,quote}]。要求真实 reading_complete、未截断的字幕/转写与原文连续引句，拒绝仅简介、未读完或未送达材料。保存正文标明作者材料主张、鱼的理解和疑问，保留视频链接、BV/CID、正文种类和版本及阅读/来源 ID。视频总结语义由鱼负责；原文引句的存在、真实阅读门槛和存储一致性由代码核验。

`video_knowledge_get` 从 Nowledge Mem 实际读回该内容版本的知识记录。ID 由视频/CID/材料种类/内容哈希确定，重试不会另建副本。成功读回且正文与请求一致才写 saved 回执；网络或格式错误保留 pending 和原草稿哈希，不假报成功。恢复时用原草稿重试。原始完整草稿保存在私有请求对象中供查证；本地仅保存控制状态与审计，知识正文的使用入口是 Mem。

专属上下文仅供已跟踪、active 且启用学习的鱼会话；无待保存实际阅读时不插入。上下文缺失时先重新读取真实 read_id 的正文，不能凭标题补写总结。平台只读限制不阻止保存自己的知识记录；仍遵循用户本轮明确限制。

## 代表性关键词与具体探索对象

阅读后的提炼类似论文关键词：从正文识别能代表内容主题、具有继续探索价值的名词或名词短语。人物、历史事件、理论名称、现象、效应、模式与抽象主题都可直接进入概念群，不必先改写成抽象大类。沿用 `topic` 标签参与兴趣竞争、关键词检索、选片及后续探索；不新增互不兼容的实体标签，也不把主题名称只标成不参加兴趣竞争的表达类 `word`。

名称被接触到（mention）、相关断言待核实、个人认同是不同问题。对某理论的批评可以产生该理论名称的探索入口，不意味着接受其结论为 belief。数量由材料和探索价值决定，先按名称/别名与语境查重，不机械采集所有名词；同名对象要用真实语境区分。具体知识、来源、总结和想法仍保存在 Nowledge Mem，两套用途可以指向同一对象。

## 补录关键词与来源完善

`watch` 与 `feed` 是阅读流程的两个阶段，阅读主题在兴趣竞争和决策校验中互通；`reply` 等其他场景仍隔离。成员可以用 `concept_enrich` 添加明确短关键词及真实正文证据：复用 candidate_id，保留原始 content/source_id 和历史，只补充 keywords/evidence，不新建副本，不增加曝光或奖励。

证据使用已有 source_id 的逐字引句，或已完整实际读完的 read_id/page/quote。关键词需出现在所附来源正文中；名称纠错可用已完整阅读材料的原始标题/简介交叉核对并保留 material_hash，不能把简介当正文。来源冲突、伪造引句、未读完材料拒绝写入。重复补证据不复制成员或同一证据。兴趣检索优先使用 keywords；多个关键词随确定性种子轮换，结果保存 keyword_sources 以追查成员/群 ID。旧数据可回退短 content/triggers，再回退群名。候选标题匹配使用全部关键词。

正常 active 探索的搜索规划包也提供并归档兴趣竞争及 keyword_sources，而不是只在旧的兼容路径计算兴趣。检索词仍由鱼按探索目标判断，不强制选中某个关键词或候选。

新 topic 主名称 content 为1–40字名词/名词短语，不接收带解释句式标点的整句；解释另存 description，关键词另存 keywords。历史长句通过 concept_enrich 的 label 原位修复，旧 content 自动保留在 description 和事件/版本中，成员 ID/source_id 不变。同主体、阅读场景中规范化同名 topic 再次 propose 会复用成员并保留新增来源，而不另建副本；同名异物需在名称中补真实语境。历史已验证队列只保留内部 legacy 回放兼容，后台自动提炼仍不启动。
